个人离线记账 App。UI 功能参考用户提供的《小账本-手机版.html》，主题采用 WinKu F2 的品牌绿 `#0E8A4A` 和中性深浅配色。原文件没有修改。

## 安装和开启自动记录

1. 把 `delivery/WinKu小账本-v1.0.0.apk` 传到手机并安装，支持 Android 8.0 及以上。第一次安装需要允许当前文件管理器安装应用。
2. 打开 App → 底部「自动记账」→「通知使用权」→「去开启」，在系统页面允许「WinKu 自动记账」。如果侧载应用被系统限制，请在应用信息菜单检查是否有「允许受限设置」，再返回开启。
3. 在「后台运行与开机恢复」中进入应用信息，按手机系统提供的选项允许自启动、后台运行。若后台不稳定，进入「电池优化」管理，将本应用设为不受限制。不同品牌名称不同。
4. 返回 App，确认显示「正在监听通知」，选择微信、支付宝或云闪付。开启这些平台自身的交易通知；若内容被隐藏，软件无法还原金额。
5. 正常使用支付平台即可。捕捉通知不需要打开交易页面；明确完成的通知直接入账，不弹窗、不抢焦点。初次使用建议检查几笔真实交易能否正确识别。

没有手机连接到本次开发环境；已在模拟器验证，尚未针对用户手机品牌、支付 App 版本和真实通知样本验证。

## 包含的功能

- 后台原生通知监听、平台开关、开机/解锁/更新后的重新绑定请求。
- 明确的付款、收款和退款自动识别并保存；金额按整数分解析。
- 重复通知事件去重；同金额的不同通知事件分别保存。
- 不明确的转账、多个金额、充值/提现、普通聊天中的交易词保留为待核对，不强行猜测。
- 通知原文收件箱、核对时预填金额/日期/备注、忽略、清理和最近 200 条诊断导出。
- 参考页面的手动增删改、分类与标签、账户、账户间转账、预算与目标、统计报表、周期规则、深浅主题、金额隐藏。
- 微信/支付宝官方 CSV 导入、通用 CSV 导入、CSV 流水导出和 JSON 完整账本备份/恢复。文件通过系统选择器操作。

## 边界与账务含义

- 记录通知不等于直接同步平台账单。没有发出的通知、隐藏的信息，以及中断期间已消失的通知，都不能补回。不能保证永不漏记或永不被系统停止。
- 「强行停止」、撤销权限、厂商后台限制会中断服务。强行停止后需要重新打开 App。
- 规则是保守推断，并未接入微信/支付宝个人账单 API。本次端到端测试使用隔离模拟器的合成通知，不是实际付款或真实支付 App 兼容认证。
- 默认仅监听微信、支付宝，云闪付可选；自定义包名仅保存交易候选通知，不自动使用通用收支规则。
- 退款单列为「退款」分类收入。普通转出暂归支出；借款、报销、内部转账可以在明细中调整。充值/提现暂不猜测账户对应关系。
- 通知通常无法确定实际扣款银行卡，自动流水默认归入对应平台账户。页面资产值仅根据已记流水与期初余额推算，不是平台实时余额。
- CSV 之间可按官方订单信息去重；通知和官方账单往往缺少共同订单号，叠加导入同一时间范围可能产生重复，请核对。
- 周期规则沿用参考页面，在打开账本或切换月份时生成；后台监听服务不会额外定时唤醒生成周期流水。

## 数据和性能

- App 没有联网权限，不上传通知或账目，没有广告、统计 SDK、Root、无障碍读取、持续截图、定时轮询或持续唤醒锁。
- 通知监听在独立 `:collector` 进程内，后台采集不加载 WebView。UI 复用系统 WebView，因此无需捆绑浏览器引擎。关闭界面后监听可以继续。
- SQLite 私有数据库存储账目，跨进程安全写入；UI 按变更合并保存，避免覆盖刚收到的后台流水。
- 通知原文默认 30 天（可选 7/90/365 天），最多 5,000 条，在新通知写入或修改保留时间时清理。账目不随原文清理。自动流水备注包含识别时的通知文本，随流水保留。
- 普通聊天默认不保存；可选保存所选平台全部通知，可能包含聊天原文。所有处理在本机；数据库未额外实现应用级加密。
- JSON 备份包含账本，不包含通知收件箱和监听设置。卸载或清除应用数据会删除本机数据，建议先导出。
- 模拟器上后台监听进程 PSS 实测约 24 MB、0 个 WebView；这不是实机耗电或性能保证。长期耗电、厂商后台策略和真实通知覆盖率需要真机试用。

## 构建与验证

使用 JDK 21+、Android SDK 37.2、Build Tools 37、Gradle 9.8.2。AGP 9.4.1；构建工具链 Kotlin 2.4.21 只参与构建，不随 App 打包。运行时代码为 Java 和系统 API，没有第三方运行时依赖。

```powershell
# 修改 local.properties 中 sdk.dir 为自己的 Android SDK 路径
$env:JAVA_HOME='你的 JDK 路径'
node .\prepare-assets.mjs
.\gradlew.bat :app:assembleRelease :app:lintRelease
```

已内置生成后的界面资源，不运行 prepare-assets 也能构建。prepare-assets 从项目内 reference 目录生成，保留原始参考文件。

本机专用发布签名保存在 `.signing`（不放进源码压缩包）。请保留此目录，以后同包名覆盖更新必须沿用签名。缺少该目录的源码构建会使用调试签名，无法直接覆盖本次发布包。

测试：

- `tests/ParserTest.java`：22 个通知解析边界用例。
- `tests/money-test.mjs`：20 个算式金额用例；WebView 与 SQLite 集成另验证 `35+12.5` 能实际保存为 47.50，无需 eval。
- `LedgerInstrumentation`：16 个 SQLite / 后台数据通路断言，包含去重、暂停、状态不明不入账、并发快照合并、删除与重启持久化。
- `tests/device-check.mjs`：模拟器端到端通知、界面关闭后的采集、重启恢复，以及界面/大字体结构检查。
- Android Lint release 检查通过；保留关于目标 SDK 和有意启用 JavaScript 的提示，不作为零警告声明。
- 手机截图位于 delivery；画面中的流水都是明确构造的测试通知，不是用户个人账目。首次安装是空账本。

`fixture` 是隔离模拟器专用的合成通知发送器，测试包名模仿微信以测试平台过滤。**不要把 fixture APK 安装到日常手机**，它不在交付安装包中。delivery 中的测试数据库仅含合成测试数据，不放进交付源码压缩包。
